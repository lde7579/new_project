# 점심 룰렛 코드 리뷰

이 프로젝트는 빌드 도구 없이 **`index.html` 한 파일**로 동작하는 앱이다.
- `<script id="wheelLogic">`: DOM을 쓰지 않는 순수 계산 로직 (`WheelLogic`). `tests/`에서 직접 테스트한다.
- `<script id="menuData" type="application/json">`: 팀 메뉴판 데이터. "HTML 저장" 기능이 이 태그를 정확히 찾아 내용을 바꾼다.
- 마지막 `<script>`: UI, 상태, localStorage, 내보내기.
- `scripts/lint.mjs`, `scripts/build.mjs`, `tests/*.test.mjs`: 외부 의존성 없이 Node로만 돈다.

## 1단계: 범위 파악
1. git 저장소이면 `git diff --staged`(없으면 `git diff`, 그것도 없으면 `git diff HEAD~1`)로 변경 범위를 확인한다.
2. git이 아니거나 변경 범위가 없으면 `index.html` 전체를 리뷰한다.
3. 변경된 줄만 보지 말고, 그 함수를 호출하거나 그 상태를 읽는 쪽까지 따라가서 확인한다.

## 2단계: 자동 검사
`npm run check`(lint → build → test)를 실행한다. 실패하면 그 내용이 가장 심각한 발견 사항이다.

## 3단계: 체크리스트 (이 프로젝트에서 실제로 깨지기 쉬운 곳)

**정확성**
- 돌림판 결과: 포인터가 가리키는 칸과 `showResult`에 넘기는 항목이 같은가? `targetRotation`/`indexAtPointer`를 거치지 않고 각도를 따로 계산하는 코드가 있으면 지적한다.
- 후보 목록: `candidates()`의 필터(카테고리 ∩ 오늘 먹은 곳 제외)가 그리기(`drawWheel`)와 돌리기(`spin`)에서 같은 배열을 쓰는가? 돌아가는 도중에 목록이 바뀌는 경우(추가·삭제·체크박스 변경)에 결과가 어긋나지 않는가?
- 오늘 기록: 날짜가 바뀌면 `eaten`이 초기화되는가? 식당을 삭제하면 `eaten`에서도 빠지는가?
- localStorage: `src`(파일에 들어 있는 원본 메뉴판)를 비교하는 로직이 유지되는가? JSON 파싱 실패 시 앱이 죽지 않는가?

**보안 / 데이터**
- 사용자가 입력한 식당 이름이 `innerHTML`이나 템플릿 문자열을 거쳐 DOM에 들어가는가? 반드시 `textContent`로 넣어야 한다. 예를 들어 이름이 `<img src=x onerror=alert(1)>`이면 어떻게 되는지 확인한다.
- HTML 내보내기: JSON 안의 `<`를 이스케이프하는가? 식당 이름에 `</script>`가 있어도 내보낸 파일이 깨지지 않아야 한다.
- 내보내기 정규식이 `menuData` 태그 하나만 바꾸는가? 태그 속성 순서나 공백이 바뀌면 조용히 실패한다.

**UX / 호환성**
- 한글 IME: Enter 처리에 `e.isComposing` 검사가 있는가? 없으면 마지막 글자가 중복 입력된다.
- `file://`에서 동작하는가? 모듈 import, fetch, 서버가 필요한 API를 쓰지 않아야 한다.
- 클립보드 API가 실패할 때 대체 동작(prompt)이 있는가?
- 빈 목록, 1개, 30개 이상일 때 돌림판과 글자가 깨지지 않는가?

**유지보수**
- 순수 로직이 UI 스크립트에 섞여 있으면 `WheelLogic`으로 옮기고 테스트를 추가하라고 제안한다.
- 새 로직에 테스트가 없으면 어떤 테스트가 필요한지 구체적으로 제안한다.

## 4단계: 보고 형식
심각도 순으로 정리한다. 확인하지 못한 추측은 "가능성"으로 따로 표시한다.

```
## 리뷰 결과: <한 줄 요약>

자동 검사: lint ✔/✖ · build ✔/✖ · test ✔/✖ (N개 통과)

### 🔴 반드시 수정 (버그·보안)
1. `index.html:123`: <무엇이 문제인지>
   - 재현: <구체적인 입력/상태> → <잘못된 결과>
   - 수정 제안: <코드 또는 방법>

### 🟡 수정 권장
### 🟢 참고 / 개선 제안
### ✅ 잘된 점 (짧게)
```

규칙:
- 모든 지적에는 `파일:줄`과 **구체적인 재현 시나리오**를 붙인다. 시나리오를 만들 수 없으면 🟢로 내리거나 뺀다.
- 스타일 취향(따옴표, 세미콜론 등)은 지적하지 않는다.
- 리뷰만 하고 파일은 수정하지 않는다. 수정은 요청받았을 때만 한다.
